# EMS 已确认参考

参考用于叙事与编辑判断，不要求其他方案照抄模块数量或标题。

- Hero：“基于 UNS，构建适合工厂的能源管理应用”。左标题、右产品图，试用与团队咨询 CTA。
- UNS：以工厂、车间、产线、设备树关联计量点、运行状态、班次、产量。对齐周期后计算单耗。
- App Builder：“自主生成 100% 定制的 EMS”；自然语言描述业务需求、功能规划、岗位职责，应用适应本厂生产流程。
- UNS Agent：“问你想问，答案都在数据里。”展示能耗分析、数据可视化卡片、定时任务，直接提问；标题是已批准营销表达，回答必须仍有实际数据支撑。
- 场景：能耗上涨时对照产量；总分表差额沿层级核查；产品单耗按同一范围与周期比较；告警交负责人处理并复查。
- 实施选择：团队自主构建 / 购买工程服务。自主路线强调团队掌控项目，服务路线写约定范围。

## 示例 prompt

为本厂生成完整的 EMS 应用，接入 UNS 中的电力、天然气、蒸汽、产量和设备状态。按车间、产线、班次展示能耗，计算产品单耗与峰谷成本，支持能源计划、超限告警、原因记录和复查。按岗位设置权限，页面和流程适应本厂生产方式。

## 内容改写

删除：“从数据接入到日常使用，分三步完成。”已有步骤展示，无信息增量。

删除：“按现场需求配置指标、阈值与统计范围。”在该稿属于笼统旁白；若其他任务需要实施说明，应写具体指标、阈值决定方式和范围，不将这句话作为万能结尾。

删除：“能耗对话示例”。对话框已经说明内容；如需标明数据是示例，在问题/回答语境中清楚呈现。

替换：“全面赋能工厂降本增效” → “按车间对比耗电量与产量，查看单位产品耗电是否增加。”

避免：“总分表差额就是能源损失”。应先核对计量覆盖、统计时间、仪表状态与分摊规则。

避免把 Demo 的 90% 预测准确率、12.5% 节能或经济收益写成真实成效。未验证就不拿来做证明。

不在每页结尾加“开始前准备什么”的通用清单；只有用户明确需要准备材料或实施指南时再加入。
