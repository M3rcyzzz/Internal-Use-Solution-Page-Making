## 每个软件方案必须保留的两个模块

用户于 2026-09-20 确认：自然语言生成部分永远沿用 EAM 构图，每个软件保留 UNS Agent 对话板块。这是本系列方案的固定要求，不因精简文案而删除；仅用户后续明确改变要求时调整。

### 自然语言构建：效果图在底，Prompt 在右下角

- 结构参考：[EAM Builder 片段](../assets/app-patterns/eam-builder.html)。复用构图和界面层级，按当前软件替换效果图、项目名、Prompt 与提示语，不能只改标题后保留 EAM 内容。
- 生成效果截图作为底层主图，Prompt 对话框位于其上层右下角；框中保留 Builder 身份、自然语言需求、当前应用名称和操作提示。桌面优先保持 EAM 的层叠比例，框小于底图、提示词可读，主图关键内容不被盖住。
- 右下角是固定视觉锚点；窄屏仍右对齐，可减少重叠或紧接底图下沿，避免遮挡与横向溢出，不为强行重叠缩小文字。不得改成左右两个无关联卡片、单独聊天框或纯文字介绍。
- 底图使用对应语言的当前应用效果，Prompt 同步翻译。示例应用效果不等于当前输入已真实执行生成；不把复制 Prompt 的预览按钮反馈成“应用已生成”。

### UNS Agent：基于当前应用的数据做业务分析与问答

- 结构参考：[EAM UNS Agent 片段](../assets/app-patterns/eam-uns-agent.html)。每个软件都必须有独立可辨识的对话板块；保留产品对话界面，不能用卖点卡片或问题清单替代。
- 先确定当前应用写入或存储在 UNS 的业务对象、记录、字段与时间范围，再构造业务问题；回答与图表、表格或列表应由这些数据支持。Source 路径须与本页 UNS 模型一致；涉及多个主题的分析提供对应来源，缺少字段时不推断答案。
- 问题随软件变化：EAM 可分析某设备的振动与维修记录；WMS 可分析某时间段的出入库差异、批次库存或临期物料；EMS 可分析班次用能与生产记录。仅采用当前方案确有或明确设计的数据，不硬套设备振动、工单场景，也不凭空补齐有效期、产量或原因字段。
- 一次简短业务提问、一段具体回答、一个相关结果以及后续输入框即可。趋势适用时画趋势，需要对比时用表格，需要跟进时列待办；不强制所有应用使用趋势卡。
- 在真实数据可用时据实回答；仅有设计资料时使用清楚标识的业务示意，保留来源映射和假设说明到交接资料。不得将示意分析写成真实查询成功、已连通数据或已创建实际定时任务。

## 界面与篇幅规则

- 应用构建模块以当前方案的应用效果截图作为底层主图，将包含需求的 Builder 输入框缩小叠放在右下角，直观呈现需求与生成结果的关系。输入文字仍须可读；省略无关侧栏、模板区，保留必要产品识别与项目选择。移动端根据宽度调整叠放比例，避免遮住主图关键内容。
- UNS Agent 用图形化对话展示具体交互，例如业务提问、数据定位、趋势卡片、添加到 Canvas、定时任务确认。避免仅列问题；示意结果不能冒充真实查询结果。

- Agent 回答区沿用截图中的产品形式：Chat / Card List 标签、正文回答、Source 路径、卡片预览及底部 Scheduled Tasks / Skills 输入区；Thinking 与步骤状态按篇幅省略；不要改成通用聊天气泡来代替产品回答结构。

- Agent 产品交互图控制在一个版块内：保留提问、回答、来源、卡片和输入区，通过紧凑间距、短步骤与适当卡片高度控制长度，避免纵向拉成多个屏幕。

- 单版块精简优先减少内容而非仅缩小字号：一次提问、一段短回答、一个相关分析结果和输入区即可。删去重复路径、步骤状态和重复完成说明，保留产品辨识度与可读性。
