# 页面视觉与交付

来源：用户在 EMS 官网落地稿中的明确选择。是后续方案页的默认基线，可被新的用户要求覆盖。

## 页面框架

- 顶部白底导航、细底边。左侧官方黑色 logo；中间 Product / Solution / Docs / Resource / Pricing，随后 Discord、GitHub 图标；右侧免费试用（英文 Free Trial）、绿色 LOG IN、语言入口。
- 使用真实可验证的官网链接，优先复用项目已有公共 header/footer。不要复制旧稿里临时指向首页的占位链接。未知链接记录在交付说明中，不制造可点击的假功能。
- 第一屏直接进入 Hero：桌面左标题、右产品图，移动端合理堆叠。主标题说明具体应用和场景。不要再加 Home / Solution / Energy Management 或 Energy management · EMS。
- Hero 与适当关键节点统一放「免费试用 / 联系团队」，英文为「Free Trial / Book a Demo」。导航与页脚中的同类 CTA 同样使用该文案；登录入口保留 LOG IN。避免每段一个 CTA。
- 白底、大留白、清楚层级、适中字体粗细。使用 design skill 的官方资产和 token；禁止用文字、CSS、AI 重画 logo。Tier0 可作为正文产品名出现。

## 页脚

- 近黑底，左侧官方白色 logo。其下订阅区文字：STAY UP TO DATE WITH PRODUCT UPDATES, LEARNING RESOURCES, AND MORE.
- 商务邮箱输入框配 Subscribe；其下 Join Discord、联系团队（英文 Book a Demo）和 LinkedIn / GitHub / Facebook / X / YouTube 社交入口，底部 Privacy Policy。
- 竖向分隔后，右侧三列目录：Tier0、Solutions、Resources。
- Tier0 作为统一产品，页脚按应用构建、Unified Namespace、App Library、Advanced Analytics、Data Collection 等功能组织入口，不拆分 Tier0 Builder 与 Tier0 Platform 产品。
- Solutions 列按 By Use Case / By Capability 分组，并有 Docs；Resources 列列 Blogs / Events / Downloads，并有 Pricing。具体目录跟随已核实官网结构，不把旧页面名称当永久清单。
- 移动端可堆叠或折叠，文字、输入与按钮可操作。预览订阅未接后台时不能假报订阅成功；使用清楚的预览行为并在交付说明中记录。

## 视觉证据

- 原始截图保留原文件；裁去浏览器栏、通知、无关项目名和系统截图小缩略图等噪声，不编造产品结果。只有相关截图才能用作功能证据。
- UNS 示例用可编辑树：Factory / Workshop / Line / Equipment，节点下 Metric / State；结合该方案所需单位、时间和对象。它是模拟数据模型，不声称实际项目已连通。
- Builder 与 UNS 的真实界面以 [产品界面参考](product-ui.md) 中的用户截图为基线；直接用图或按原图制作可编辑 HTML，按当前用户要求选择。Builder 的提示词与项目名贴合当前方案。Agent 用简短问题、数据表或图、可执行下一步展示。原生 HTML/SVG 用于图形与文字；栅格图片用于真实界面与照片。
- 保留语义正文、表格标题和必要可访问文本。不要为了视觉简洁把关键语义只藏在 alt 或 aria-label 中。
- 尽量一个模块一个问题。没有内容增量就删掉副标题、小字和重复引导。
- 流程用步骤与箭头，层级用树，关联用关系图，差异用简表；选最能解释当前问题的形式，不把长段落塞进框里冒充图形。图形已说明的信息不再逐项复述，短文只补结论与必要前提。

## 双语图片与界面本地化

- 先将每个图片位置与语言版本对应：用户提供了双语截图，核对是否为同一功能、状态和版本后直接分别使用；只提供单语截图，需将该页实际使用的截图转换为另一语言，不能默认英文页继续放中文截图，反向亦然。无需转换未采用的全部附件。
- 翻译截图内的菜单、标题、字段、按钮、状态、提示、示例说明及图形标签；保留品牌、编码、单号、数量、日期、单位与业务状态，统一 UI 术语。不要凭翻译增加功能、修改结果或虚构客户数据。
- 保留原图，译图另存并记录对应关系。优先采用可用的真实目标语言界面；没有时制作本地化衍生图，使用当前环境允许的图片编辑或可编辑界面重建方式。译文应清晰可读，保留布局与视觉层级，检查长词换行、截断、重叠和小字，不靠简单放大冒充高清。
- 页面正文、图形标签、图片说明、alt、交互提示与截图一起匹配语言。逐张视觉核对翻译完整性、关键数值和布局，并检查语言切换与资源路径。不能只检查 alt 就宣称图片已翻译。
- 在素材映射或交接说明中区分真实目标语言截图和本地化衍生图；后者不能证明软件已支持该语言或相应功能。正文无需追加泛化免责声明。无法可靠转换的内容明确列为未完成，不用含糊标注掩盖。

## 设计交付

- 如用户需要上线效果图，默认交付响应式 HTML、对应素材、源稿与 SEO 说明；复用现有技术栈，不擅自换平台。
- 双语默认独立可链接 URL，语言切换到对应页面；图片遵守上述本地化规则，不将译制图称为真实产品原始截图。
- 向设计团队交付时包含：中英稿、源 HTML/组件、真实原图、官方 logo、字体及许可（允许分发时）、素材映射、未接入功能和待核实链接说明。
- 核实实际像素和导出尺寸。放大图片明确叫放大版；要清楚文字优先矢量排版加原图，不反复让图像模型重绘产品小字。

- 截图下的补充正文与所属模块对齐，使用正常正文字号和自然换行；避免额外窄宽度造成意外断行。Namespace 与 Agent 均以单个紧凑版块展示，优先删重复内容，不能靠持续缩小字号解决高度。

## 底部服务模式固定模块

底部服务模式按 [EMS 固定参考](service-modes.md) 原样复用，只替换当前应用名称与专业内容。该局部模块的标签、按钮文字、两栏列表与样式优先于本文件通用 CTA 和不加装饰小字的默认要求；页面其他区域仍沿用原规则。
